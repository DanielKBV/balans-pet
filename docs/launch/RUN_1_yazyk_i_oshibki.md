# RUN 1. Английский язык и ключевые ошибки

Сначала загрузи skill `balans-launch` и прочитай `docs/launch/PROGRESS.md`, `docs/TZ.md`, `docs/DESIGN.md`, `CLAUDE.md`, `docs/launch/SLOVAR_EN.md`. Работай по правилам skill: ворота качества после каждой фазы, остановки только в точках СТОП.

## Цель

Заказчик с Upwork или иностранный тимлид открывает сайт и видит весь продукт на английском: вход, кабинет, демо. Русский остаётся для местных работодателей. Заодно закрываем ключевые ошибки из аудита.

## Решения (уже приняты, не пересматривать)

- **next-intl без префикса в адресе.** Язык хранится в cookie, маршруты не переносим в `[locale]`. Причина: продукт готов, срок 2 дня, перенос маршрутов и склейка с Supabase в `src/proxy.ts` — самый рискованный путь. Адреса `/ru` и `/en` записаны в «После запуска».
- **Какой язык показать:** cookie → язык браузера (русский или кыргызский → `ru`) → иначе `en`. Без cookie и без подсказки браузера (боты, превью ссылок) — `en`.
- **Ссылка на английский:** `/?lang=en` и `/?lang=ru` ставят cookie и ведут на чистый адрес. Работает на любой странице.
- **Переключатель RU / EN** в шапке лендинга, на страницах входа и в кабинете, рядом с переключателем темы (на лендинге и гостевых страницах переключатель темы уберёт RUN 2, языковой остаётся).
- **Деньги:** `16 000 сом` в русском, `16,000 KGS` в английском. Даты по языку. Часовой пояс Бишкека для обоих.
- **Не переводим:** `/admin` и `/design` (остаются на русском).
- **Тело лендинга не переводим:** его с нуля переделывает RUN 2 сразу на двух языках. В RUN 1 переводим только общую шапку и подвал.

## Фазы

### Фаза 0. Разведка (без кода)

Ветка `launch/run-1`. Проверь по коду, что решения выше ложатся на проект: как устроены `src/proxy.ts`, корневой layout, `src/lib/format.ts`, `src/lib/month.ts`, `src/lib/auth-errors.ts`, схемы форм, миграции `0001`, `0005`, `0006`, `0007`. Через context7 возьми актуальную документацию next-intl для Next 16 (режим без i18n-маршрутизации). Собери свежий список текстов с путями. Запиши короткий план в `PROGRESS.md`. Если видишь, что какое-то решение выше не работает с этим кодом, остановись и объясни, иначе продолжай.

### Фаза 1. Основа

next-intl, словари `messages/ru.json` и `messages/en.json` с понятной структурой ключей по страницам, провайдер, определение языка, `?lang=`, переключатель, `<html lang>`, функции форматирования с языком, русские формы множественного числа.

Правка `src/proxy.ts` минимальная: только обработка `?lang=`. Ответ Supabase и его cookie должны остаться нетронутыми (см. комментарии Supabase в самом файле: возвращать тот же объект ответа, а при редиректе копировать cookie).

Готово, когда: переключатель меняет язык без потери входа, сценарий входа из ворот качества проходит на обоих языках.

### Фаза 2. Тексты гостевых страниц

Вход, регистрация, новый пароль, создание бизнеса, приглашение, `/privacy`, 404, страницы ошибок, шапка и подвал, `public/offline.html` (это статичный файл: покажи обе строки, английскую и русскую). Ошибки проверки форм и словарь ошибок Supabase на двух языках. `title` и `description` этих страниц.

### Фаза 3. Тексты кабинета

Цели 44 px в подвале и логотипе не чини: лендинг переделывается в RUN 2, это требование записано там.

### Фаза 5. База и письма

Одна новая миграция (файл в папке миграций, следующий номер):
- у бизнеса появляется язык; стартовые категории создаются на языке, который был выбран в момент создания бизнеса (названия в `SLOVAR_EN.md`);
- английское демо «Azamat's Car Wash» с теми же данными, что у русского; кнопка демо открывает демо на текущем языке;
- если SQL-функции возвращают русский текст ошибки, заменить на коды, а текст брать из словарей.

Существующие политики RLS не менять. Миграция должна безопасно применяться к живой базе с данными: существующие бизнесы получают язык `ru`, ничего не удаляется.

Подготовь тексты двух писем Supabase (подтверждение почты, сброс пароля) в одном шаблоне на двух языках: сначала английский, ниже русский. Положи в `docs/launch/supabase_emails.md`.

Не переносить маршруты в `[locale]`. Не менять дизайн страниц. Не трогать политики RLS. Не переводить тело лендинга. Не добавлять кыргызский.
