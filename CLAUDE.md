# Balans

Онлайн-тетрадь доходов и расходов для небольшого бизнеса услуг (автомойка, барбершоп, СТО). Pet-проект для портфолио.

**Полное ТЗ: [docs/TZ.md](docs/TZ.md). Читать перед каждой задачей.** Работа идёт по этапам из раздела 7 ТЗ, по одному этапу за раз.

## Стек

- Next.js 16 (App Router) + TypeScript, папка `src/`
- Tailwind CSS v4 + shadcn/ui (стиль `base-nova`, примитивы Base UI, иконки `lucide-react`)
- Supabase: PostgreSQL, Auth (email + пароль, Google), RLS — с этапа 2
- Хостинг Vercel, код на GitHub (публичный репозиторий `balans`)
- Отдельного бэкенда нет: серверные действия и route handlers Next.js + Supabase

Next.js 16 отличается от того, что ты знаешь по обучению. Перед кодом смотри документацию в `node_modules/next/dist/docs/` (см. AGENTS.md).

## Правила продукта

- Интерфейс только на русском.
- Деньги только в сомах, целые числа, без тыйынов. Выбора валюты нет.
- Часовой пояс: Asia/Bishkek.
- Права доступа проверяются в базе (Supabase RLS). Скрытие кнопок в интерфейсе — только для удобства, не защита.
- Один бизнес никогда не видит данные другого. Сотрудник не видит итогов и прибыли.
- Доход — зелёный, расход — красный. Светлая и тёмная тема, по умолчанию как в системе.
- В каждом списке и графике три состояния: загрузка, пусто, ошибка (с кнопкой «Повторить»).

## Дизайн-система

Любой интерфейс в проекте делается только по [`docs/DESIGN.md`](docs/DESIGN.md) и токенам темы (`src/app/globals.css`). Если нужного токена или компонента нет, сначала добавь его в дизайн-систему, потом используй. Живая витрина: страница `/design`.

## Адаптив: задача с интерфейсом готова только после проверки на 6 ширинах

| Ширина | Что это |
|---|---|
| 360 px | Маленький телефон |
| 390 px | Обычный телефон |
| 768 px | iPad вертикально |
| 1024 px | iPad горизонтально, маленький ноутбук |
| 1440 px | Ноутбук |
| 1920 px | Большой монитор |

- Верстаем от телефона (базовые классы Tailwind — узкий экран, дальше `sm:`/`md:`/`lg:`), но телефон и компьютер делаются в одной задаче.
- Нигде нет горизонтальной прокрутки страницы. Широкая таблица прокручивается внутри своего блока или на телефоне становится карточками.
- На больших мониторах у содержимого есть максимальная ширина.
- Кнопки и поля на телефоне не ниже 44 px.
- **В конце каждой задачи с интерфейсом запускай skill `check-screens`** (`npm run check:screens -- <пути>`) и показывай результат.

## Как работаем

- Один этап за раз. Сначала план, потом код.
- Всё, что сверх текущего этапа, не делаем, а записываем в раздел 8 ТЗ («Версия 2»).
- В конце этапа объясняем простыми словами, что сделано и почему.
- Коммиты и push — только по явной команде пользователя.
