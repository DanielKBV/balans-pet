# Проверка экранов

Задача с интерфейсом не считается готовой, пока эта проверка не пройдена.

## Как запустить

```bash
npm run check:screens -- / /login
```

- Аргументы: пути страниц, которые затронула задача. Без аргументов проверяется `/`.
- Скрипт сам поднимает временный `next dev` на порту 3100 и сам его останавливает после проверки. Висящих процессов не остаётся.
- Если сервер уже запущен пользователем, можно проверить его: `BASE_URL=http://localhost:3000 npm run check:screens -- /`.
- Закрытые страницы (кабинет) пока проверяются только после входа. Когда появится авторизация, скрипт нужно будет научить входить в тестовый аккаунт.

## Что делает

1. Открывает каждую страницу в Chromium на ширинах 360, 390, 768, 1024, 1440, 1920 px, каждую ширину в светлой и тёмной теме (системная тема браузера, сайт по умолчанию её повторяет). Итого 12 снимков на страницу.
2. Сохраняет скриншот всей страницы в `.screenshots/<страница>-<тема>-<ширина>.png`, например `design-dark-360.png` (папка в `.gitignore`).
3. Сравнивает ширину содержимого с шириной окна. Если содержимое шире — страница прокручивается вбок, это ошибка (`FAIL`, код выхода 1).

## Что делать с результатом

1. Прочитать вывод скрипта. Любой `FAIL` — исправить и запустить снова.
2. Открыть скриншоты (Read по файлу `.png`) хотя бы для 360, 768 и 1440 в обеих темах и глазами проверить по правилам из `CLAUDE.md`:
   - на телефоне кнопки и поля не ниже 44 px, ничего не обрезано;
   - на 1920 содержимое не растянуто во всю ширину (есть максимальная ширина);
   - таблицы прокручиваются внутри своего блока или становятся карточками.
3. Показать пользователю короткую сводку: таблица ширина × тема → OK/FAIL и что было замечено на скриншотах.

Длинную страницу целиком Read сильно уменьшает. Если нужны детали, снимать её частями (`clip`) или отдельные блоки (`locator(...).screenshot()`).
