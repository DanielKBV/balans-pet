# RUN 2B. Лендинг по утверждённому прототипу (с 3D)

Этот файл заменяет оставшуюся часть RUN 2 (лендинг) и весь RUN 3 (3D). RUN 4 (SEO и финал) остаётся как был.

Сначала загрузи skill `balans-launch` и прочитай `docs/launch/PROGRESS.md`, `docs/DESIGN.md`. Загрузи skills: `frontend-design`, `impeccable`, `react-best-practices`, `gsap-react`, `gsap-scrolltrigger`, `gsap-performance`, `threejs-react-three-fiber`, `threejs-performance`, `threejs-materials`, `threejs-lighting`, `core-web-vitals`, `accessibility`. Документацию R3F, drei, GSAP, next-intl бери через context7. Работай по правилам skill `balans-launch`: ворота качества, бюджет скорости, формат СТОП.

## Главное

**Образец — прототип, а не этот текст.** Файл `docs/launch/prototype/balans_landing_prototype.html` Даниэл посмотрел и утвердил. Открой его в браузере через Chrome DevTools MCP, прокрути, наведи курсор на карточки, сделай скриншоты. Прочитай его код: там все анимации, тайминги, цвета и 3D-сцена. Если текст ниже и прототип расходятся, прав **прототип**. В конце каждого этапа сравни свои скриншоты со скриншотами прототипа на тех же ширинах (1440 и 390).

Из прототипа **не** переносим: жёлтые подписи «Блок N», нижнюю панель переключения вариантов, варианты hero A и C (утверждён **B**), блок 4 «Как это работает» (в варианте B он уже внутри hero), серые заглушки (вместо них настоящие компоненты Balans).

**Зачем лендинг.** Он продаёт Balans как настоящий продукт владельцу автомойки или барбершопа: проблема → как работает → что видно в кабинете → возможности → демо. Работодатель увидит качество сам. Стек, RLS и код **не показываем**. Об авторе говорит только подвал.

**Убрать с нынешнего лендинга:** главный блок с картинкой-столбиками, блок «Как это сделано», отдельный блок «Автор», кнопку «Код на GitHub» в hero, подпись «Pet-проект · …» над заголовком. Окно кабинета из настоящих компонентов **оставить** и доработать (блок 3).

## Блок 1. Hero B

**Как работает.** Секция высотой около 340vh. Внутри закреплённый (sticky/pin) экран высотой со окно браузера: слева текст шага, справа 3D-сцена. Прогресс прокрутки секции `p` от 0 до 1 управляет всем:

| p | Шаг (текст слева) | Экран в 3D | Монеты |
|---|---|---|---|
| 0–0,30 | Заголовок, подзаголовок, кнопка «Открыть демо», «Листайте вниз ↓» | «Сегодня»: список из 5 серых строк | Плавают вокруг экрана |
| 0,30–0,66 | Шаг 1. Администратор вносит выручку | Форма записи: «Доход», сумма растёт 0 → 5 400 сом, выбрана «Комплексная мойка», кнопка «Сохранить» | С 0,18 по одной влетают в экран и исчезают |
| 0,66–1 | Шаг 2. Владелец видит прибыль | «Прибыль за ноябрь» растёт 0 → 142 800 сом, мини-график | Нет; справа вырастают 3 столбика (зелёный, красный, зелёный) |

Экран поворачивается по оси Y от −0,75 до +0,3 рад по ходу прокрутки, слегка следует за мышью (на компьютере), медленно покачивается. Внизу слева 3 полоски прогресса шагов. Тексты шагов сменяются плавно (opacity + сдвиг), точные значения в прототипе.

**3D-объекты (всё кодом, без загружаемых моделей):**
- **Экран-карточка**, не телефон: скруглённый прямоугольник 2,5 × 5 с толщиной и фаской (`ExtrudeGeometry` из скруглённой формы, bevel), тёмный металл с лаком (`MeshPhysicalMaterial`, clearcoat). Без кнопок и выреза под камеру. На лицевой стороне скруглённая плоскость с текстурой интерфейса, нарисованной на `<canvas>` (как в прототипе, функция `draw`). Перерисовывать текстуру только когда меняется шаг или число.
- **Монеты:** ребристый край (bump-текстура полос), выпуклый ободок (тор) с двух сторон, на лицевой стороне выбит символ (карта + bump из canvas). Виды и металл:

  | Вид | Символ | Цвет металла |
  |---|---|---|
  | som (главный, их больше всех) | знак сома: буква С и черта под ней (рисуется дугой и прямоугольником, не шрифтом) | серебро `#c6cad4` |
  | b | B | индиго `#7774ff` |
  | usd | $ | золото `#d9b45e` |
  | eur | € | `#b9c3d6` |
  | rub | ₽ | бронза `#c08457` |
  | btc | ₿ | `#e3a24a` |

  Одна геометрия на все монеты, материалы кешируются по виду. Набор в hero: som, usd, b, eur, som, btc, rub.
- **Свет:** окружение из «софтбоксов» через `PMREMGenerator` (функция `makeEnv` в прототипе) или эквивалент drei `<Environment>` с `Lightformer` без загрузки HDR-файла. Плюс слабый ambient, один направленный свет и индиговый контровой. Без теней.
- Прототип написан на three r128. В новой версии three названия другие (`outputColorSpace`, `SRGBColorSpace`, физические единицы света). Подбери значения на глаз по скриншотам прототипа.

**Реализация.** R3F (`@react-three/fiber`) и только нужное из drei. Прогресс прокрутки через GSAP ScrollTrigger (`scrub`) или собственный расчёт, но одно значение `p` на всю сцену. Сцена в отдельном клиентском компоненте через `next/dynamic` с `ssr:false`, грузится после показа страницы, когда браузер свободен.

**Скорость и запасной вариант** (правила 3D из skill `balans-launch` действуют полностью):
- Сначала видна картинка-poster: скриншот сцены на шаге 0, снятый Playwright. Подмена на canvas плавная, без сдвига вёрстки. LCP — заголовок, не canvas.
- DPR: на телефоне 1, на компьютере не больше 1,5. Кадры не рисуются, когда секция за экраном или вкладка скрыта.
- Картинка вместо 3D: «уменьшить движение», нет WebGL, экономия трафика, слабое устройство, низкий FPS на нижней ступени, потеря контекста, `NEXT_PUBLIC_HERO_3D=off`. В режиме картинки три шага всё равно сменяются при прокрутке: меняются 3 статичные картинки экрана (снять их тоже Playwright).
- **Телефон:** сцена сверху (около 52% высоты), текст шага снизу, как в прототипе на 390 px. Canvas не перехватывает касания.
- Canvas скрыт от экранного диктора. Тексты всех трёх шагов есть в DOM.

## Блок 2. Проблема

- Большая фраза загорается по словам при прокрутке: сначала слова тёмно-серые, по мере прокрутки становятся белыми (scrub, только `color` или `opacity`).
- 3 карточки, при наведении (на телефоне — сами, когда карточка появилась на экране) играют мини-анимацию:
  1. «Тетрадь теряется»: строки записей уезжают вправо и бледнеют.
  2. «Excel с телефона мучение»: сетка ячеек, по ней прыгает рамка-курсор, 3 ячейки краснеют по очереди, в конце появляется плашка «#ЗНАЧ!».
  3. «Деньги уходят незаметно»: зелёные столбики краснеют и опускаются.
- У всех карточек подсветка за курсором (см. блок 5).

## Блок 3. Живой кабинет

Нынешнее окно кабинета из настоящих компонентов остаётся. Добавить:
- Окно стоит с наклоном (`rotateX` 22° и `scale` 0,9) и выпрямляется до 0° и 1 по мере прокрутки, пока подходит к центру экрана.
- Числа в карточках считаются от 0 при первом появлении (около 1,4 с).
- Пока окно на экране, каждые ~3,2 с сверху в «Последние записи» въезжает новая запись, нижняя уходит. Выручка и прибыль меняются на сумму записи и коротко подсвечиваются. Записи берутся из списка демо-операций автомойки, без выдуманных клиентов.
- Столбики графика вырастают при появлении.
- 2 пульсирующие точки-подсказки (на «Прибыль» и на «Последние записи»). Подсказка открывается **вниз и выровнена по правому краю**, не обрезается. На телефоне открывается по нажатию.
- Тень окна с лёгким индиговым свечением, подсветка за курсором.
- На телефоне без бокового меню, без горизонтальной прокрутки.

## Блок 5. Возможности (bento)

Сетка 6 колонок: [Запись за минуту — 4][Сотрудник не видит прибыль — 2] / [Команда по ссылке — 2][Куда ушли деньги — 4]. На телефоне одна колонка.

У каждой карточки:
- **Подсветка за курсором:** CSS-переменные `--mx`/`--my` обновляются на `pointermove`; мягкий индиговый круг внутри и светящаяся рамка по маске (как в прототипе, `.spot::before` и `::after`). Без библиотек.
- Мини-интерфейс из настоящих компонентов Balans и анимация при наведении (на телефоне один раз, когда карточка появилась):
  1. Запись за минуту: сумма «5 400» печатается по символу, выбирается чип «Комплексная мойка», кнопка нажимается, появляется «✓ Сохранено».
  2. Сотрудник не видит прибыль: переключатель Владелец → Сотрудник, сумма размывается, появляется «🔒 Скрыто для сотрудника».
  3. Команда по ссылке: «Скопировать» → «✓ Скопировано», въезжают 3 аватара.
  4. Куда ушли деньги: полосы категорий вырастают до своих долей (Зарплата 48%, Аренда 25%, Шампунь, химия 18%, Прочее 9%).

## Общие детали

- **Живые стрелки** на всех кнопках со стрелкой: SVG из двух путей, линия появляется, наконечник сдвигается на 3 px при наведении (как в прототипе `.arr`).

## Этапы

Ветка `launch/run-2` (продолжаем её). Коммит после каждого этапа.

**Этап 1. Блоки 2, 3, 5, 6, 7 и меню.** Убрать старое (см. «Главное»), собрать новые блоки, положить фото. Hero пока: текст шага 0 + картинка-заглушка нужных пропорций. Ворота качества, скриншоты 1440 и 390 рядом со скриншотами прототипа.

**Этап 2. Hero B с 3D.** Сцена, прокрутка, шаги, монеты, poster и 3 картинки шагов, все запасные варианты, телефонная вёрстка. Проверка на 1024, 1440, 1920, 360, 390, 768.

**Этап 3. Скорость.** `perf-auditor`. Бюджет из skill. Чанк three.js не в первом экране. До 3 кругов исправлений; если на телефоне бюджет не выполнен, на телефоне остаются картинки шагов, и это честно пишется в отчёте. Скорость важнее 3D. Записать в `docs/LANDING.md` раздел «Как устроено 3D и почему оно быстрое» простыми словами.

**Этап 4. Фон пустых страниц** (вход, регистрация, 404 и др., бывшая Фаза 3 RUN 2): медленно плавающие CSS/SVG-монеты со знаком сома и B в стиле hero, без three.js. Правила те же, что были в RUN 2.
