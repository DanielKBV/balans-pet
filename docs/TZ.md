# ТЗ: pet-проект Balans

Версия 1, 2026-10-08 (правки Даниэла: только сом, адаптив, PWA, сброс пароля, название).

**Название продукта: Balans.** Пишется латиницей, с заглавной буквы. Так называются сайт, репозиторий на GitHub (`balans`), проект в Supabase и Vercel, приложение на телефоне. По-русски в тексте можно «Баланс».

Этот документ для Claude Code. Здесь только **что** делаем и **какие сервисы** берём. **Как** писать код (библиотеки помельче, где SSR, где клиентский компонент, структура папок, названия) решает Claude Code сам на каждом этапе.

## 1. Продукт одной страницей

**Что это:** онлайн-тетрадь доходов и расходов для небольшого сервиса, которая сама считает прибыль.

**Для кого:** владелец небольшого бизнеса услуг с 1–5 сотрудниками. Главный пример — автомойка. Подходит и барбершопу, салону, СТО. Товаров и склада нет, только деньги.

**Проблема:** владелец не знает точно, сколько заработал за месяц и куда уходят деньги. Тетрадь теряется, Excel неудобно вести с телефона.

**Как пользуются:**
- Каждый день в конце смены администратор с телефона вносит выручку и расходы. Это занимает минуту.
- Раз в неделю или месяц владелец открывает кабинет с ноутбука и видит выручку, расходы, прибыль и на что ушло больше всего.

**Чего в продукте нет (и не будет в версии 1):** товаров, склада, остатков, кассы, чеков, налогов, бухгалтерии, мобильного приложения, рассылки писем, AI.

## 2. Роли

| Роль | Кто это | Что может |
|---|---|---|
| **Гость** | Не вошёл | Смотрит лендинг, регистрируется, входит, открывает демо |
| **Владелец** | Создал бизнес | Всё внутри своего бизнеса: записи, итоги, графики, категории, команда, настройки |
| **Сотрудник** | Пришёл по приглашению | Добавляет записи и видит только свои. Итогов, прибыли и чужих записей не видит |
| **Суперадмин** | Даниэл | Видит список всех бизнесов и пользователей. Чужие записи не редактирует. Последний этап |

**Правила, которые важно не нарушить:**
- Один бизнес не видит данные другого. Никогда, ни через интерфейс, ни через прямой запрос к базе.
- Сотрудник не видит суммы итогов и прибыль, даже если вручную наберёт адрес страницы владельца.
- Эти правила проверяются **в базе** (Supabase RLS), а не только скрытием кнопок. Скрытие кнопок только для удобства.

**Упрощения версии 1:**
- Один пользователь состоит в одном бизнесе.
- В бизнесе один владелец.
- Сотрудник может исправить или удалить свою запись в течение 24 часов после того, как внёс её (решение Даниэла 2026-11-05: 24 часа понятнее, чем «тот же день»). Более старые записи меняет только владелец.

## 3. Сервисы и главные решения

| Вопрос | Решение | Почему |
|---|---|---|
| Фреймворк | **Next.js 16 + TypeScript** | Решено заранее, его ищут в вакансиях |
| Стили | **Tailwind + shadcn/ui** | Готовые компоненты, вид «как Stripe/Linear» почти без своего дизайна |
| Нужен ли бэкенд отдельно | **Нет** | Хватает Next.js (серверные действия и роуты) и Supabase |
| База данных | **Supabase (PostgreSQL)**, бесплатный тариф | База, вход и права в одном месте, Даниэл с ним уже работал |
| Авторизация | **Supabase Auth, не вручную** | Ручная авторизация (пароли, сессии, сброс) долгая и опасная. Supabase даёт это готовым |
| Способы входа | **Email + пароль** и **Google** | Google, чтобы вход был в один клик |
| Права доступа | **RLS в Supabase** | Правила «кто что видит» живут в базе |
| Приглашение сотрудника | **Ссылка-приглашение**, без отправки писем | Отправка писем требует почтового сервиса. Ссылку владелец сам кидает в WhatsApp/Telegram |
| Таблицы | shadcn Data Table (на TanStack Table) в серверном режиме (`manualPagination`, `manualSorting`, `manualFiltering`) | Фильтры, сортировка, страницы; TanStack часто просят в вакансиях. Фильтрует и делит на страницы база, параметры в адресе страницы: в браузер не грузятся все записи (решено 2026-11-04) |
| Графики | shadcn Charts | Уже в стиле остального интерфейса |
| Формы | React Hook Form + Zod, поля shadcn `Field` | Одна схема Zod проверяет и в браузере, и на сервере. Для формы из одного поля библиотека не нужна (решение Даниэла 2026-11-04) |
| Хостинг | **Vercel**, бесплатный тариф | Деплой из GitHub при каждом пуше |
| Код | **GitHub**, публичный репозиторий | Его увидит работодатель |
| Оплата | **Не в версии 1.** Позже по желанию, только тестовый режим | См. раздел 8 |
| Язык интерфейса | Русский | Один язык, без переключения |
| Стоимость | **$0** | Всё на бесплатных тарифах |

**Про бесплатный Supabase:** проект «засыпает», если им не пользоваться 7 дней. Будится одной кнопкой в панели Supabase. Перед собеседованием стоит открыть сайт и проверить, что он работает.

**Деньги:** только сом. Суммы целые, без тыйынов. Выбора валюты нет. Часовой пояс Бишкека.

**Письма:** Supabase сам отправляет два вида писем: подтверждение почты при регистрации и ссылку «Забыли пароль». Отдельный почтовый сервис не нужен. У встроенной почты Supabase есть лимит в несколько писем в час, для pet-проекта этого хватает.

## 4. Данные (простыми словами)

Не названия таблиц, а что хранит продукт. Как это разложить по таблицам, решает Claude Code.

- **Бизнес:** название, вид деятельности, когда создан.
- **Участник бизнеса:** какой пользователь, в каком бизнесе, какая роль (владелец или сотрудник).
- **Приглашение:** для какого бизнеса, до какого числа действует, использовано или нет.
- **Категория:** название, тип (доход или расход), бизнес. Можно скрыть, но не удалить, если по ней уже есть записи.
- **Операция (запись):** доход или расход, сумма, категория, дата, комментарий, кто внёс, когда внёс.

При создании бизнеса автоматически добавляются стартовые категории для автомойки:
- Доходы: Мойка кузова, Комплексная мойка, Химчистка салона, Прочее.
- Расходы: Аренда, Зарплата, Расходники (шампунь, воск), Коммунальные, Прочее.

## 5. Стиль

- Образец: блок **dashboard-01** с [ui.shadcn.com/blocks](https://ui.shadcn.com/blocks). Меню слева, сверху карточки с цифрами, ниже график и таблица.
- **Светлая и тёмная тема**, переключатель в шапке. По умолчанию как в системе.
- Цвета спокойные, нейтральный серый фон, один акцентный цвет. Доход зелёный, расход красный.
- Шрифт один, без украшений. Тонкие границы, мало теней.
- **Телефон:** меню слева превращается в нижнее меню или «бургер». Форма добавления записи крупная, удобная для пальца: сумма с цифровой клавиатурой, категории кнопками.
- **Компьютер:** таблица и графики во всю ширину.
- В каждом списке и графике есть три состояния: **загрузка**, **пусто** («Записей пока нет, добавьте первую»), **ошибка** (понятный текст и кнопка «Повторить»).


### Логотип и иконка

- Логотип: белая заглавная буква **B** в квадрате со скруглёнными углами, фон квадрата в акцентном цвете. Рядом слово **Balans** простым шрифтом.
- Та же иконка без слова используется как favicon во вкладке браузера и как иконка PWA на телефоне.
- Иконку делает Claude Code (SVG и нужные размеры PNG). Отдельный дизайнер и графические программы не нужны.

### 5.1. Адаптив: телефон и компьютер делаются одновременно

Не «сначала мобилка, потом десктоп» отдельными этапами. Каждую страницу верстаем **от телефона** (так устроен Tailwind: базовые стили для узкого экрана, дальше добавки для широких), но страница **не считается готовой**, пока не проверена на всех ширинах:

| Ширина | Что это |
|---|---|
| 360 px | Маленький телефон |
| 390 px | Обычный телефон |
| 768 px | iPad вертикально |
| 1024 px | iPad горизонтально, маленький ноутбук |
| 1440 px | Ноутбук |
| 1920 px | Большой монитор |

Правила для всех страниц:
- Нигде нет горизонтальной прокрутки страницы. Широкая таблица прокручивается внутри своего блока или на телефоне превращается в карточки.
- На больших мониторах содержимое не растягивается во всю ширину, у него есть максимальная ширина.
- Кнопки и поля на телефоне не меньше 44 px по высоте, чтобы попадать пальцем.

**Как это закрепить в Claude Code (делается на этапе 0):**
1. Записать правило и таблицу ширин в `CLAUDE.md` проекта: «задача с интерфейсом готова только после проверки на 6 ширинах».
2. Попросить Claude Code создать в проекте skill проверки экранов: он открывает страницу в браузере (Playwright) на 6 ширинах, делает скриншоты, проверяет, что нет горизонтальной прокрутки, и показывает результат. Claude Code запускает его в конце каждой задачи с интерфейсом.

### 5.2. PWA

Сайт можно **установить на телефон** как приложение: иконка на главном экране, открывается на весь экран без адресной строки. Для администратора, который каждый вечер вносит записи, это удобно.

В версии 1: иконка, название, цвет темы, установка на телефон (Android и iPhone). Без интернета приложение показывает понятное сообщение «нет соединения». Работа **без интернета** с отправкой записей позже уходит в версию 2, потому что это отдельная сложная задача.

| № | Страница | Что на ней |

**Демо-режим.** Кнопка «Посмотреть демо» на лендинге входит в готовый бизнес «Автомойка Азамата» с данными за 3–4 месяца. Так работодатель сразу видит графики, не регистрируясь. Демо-данные можно сбрасывать.

Решение Даниэла 2026-11-12: у каждого гостя своя копия. «Посмотреть демо» анонимно входит (anonymous sign-in Supabase) и создаёт гостю свежую «Автомойку Азамата», гости не мешают друг другу. Демо-бизнесы удаляются через сутки.

Список «потом». Сюда же складываются все новые идеи и сомнения, которые появятся во время работы.

- **Экспорт в Excel** за выбранный период.
- **Тарифы и оплата в тестовом режиме:** Free до 100 записей в месяц, Pro без лимита. Stripe в тестовом режиме или Polar sandbox, выбрать на этом этапе (у Stripe могут быть ограничения при регистрации из Кыргызстана, это нужно проверить тогда).
- **Офлайн-режим PWA:** вносить записи без интернета и отправлять, когда интернет появится.
- **Подтверждение почты при регистрации по паролю.** Отклонение от разделов 3 и 7: выключено осознанно (решение Даниэла 2026-11-02, в Supabase `mailer_autoconfirm: true`). Без него можно зарегистрироваться на чужой Gmail, и потом вход владельца через Google может слиться с этим аккаунтом. Включить до показа работодателю, рассмотреть вместе со входом через Google. Для этого передать `emailRedirectTo` в `signUp`; учесть лимит встроенной почты Supabase (несколько писем в час).

## 9. Как передавать в Claude Code

1. Положить этот файл в репозиторий (например, `docs/TZ.md`) и сослаться на него в `CLAUDE.md`, чтобы Claude Code читал его в каждой сессии.
2. Давать по одному этапу: «Сделай этап 4 из docs/TZ.md. Сначала расскажи план, потом пиши код».
3. В конце этапа просить: «Объясни, что ты сделал и почему, простыми словами». Если непонятно, переспрашивать, пока не станет понятно. На собеседовании спросят именно это.
4. Если Claude Code предлагает добавить что-то сверх этапа, записывать в раздел 8 и не делать сейчас.
